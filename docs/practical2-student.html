Speed control with P and PI

Learning task: explain why proportional control leaves a speed offset, show how integral action removes that offset in the ideal stable model, then tune and evaluate the real motor.

Reuse the motor model and kit settings from Practical 1. Do not repeat identification, motor-parameter measurements or P1 model validation. Position is an optional simulation-only extension; no position hardware trials are required.

1. Bring forward the P1 model

Use your existing voltage-to-output-speed model, with output speed in rad/s:

GP1(s) = K̄ / (τ̄s + 1)

The speed-control page uses motor-shaft RPM and signed fractional duty u (0.40 means 40%). With actual declared supply Vs and motor/output gearbox ratio N:

G(s) = K / (τs + 1),   K = K̄ × N × 60/(2π) × Vs,   τ = τ̄

This conversion assumes Vmotor ≈ Vsu. Driver losses, friction and model uncertainty may cause disagreement. K is the plant gain, not the Ziegler–Nichols ultimate gain. Enter the ratio applicable to your kit; do not multiply the encoder counts by N and divide by N a second time.

2. Analyse and simulate P-only control

Use unity negative feedback, e = r − n, and C(s) = Kp. Derive or verify:

TP(s) = KKp / (τs + 1 + KKp)
QuantityIdeal, unsaturated first-order result
Closed-loop time constantτcl = τ / (1 + KKp)
Final speedn∞ = r KKp / (1 + KKp)
Fractional steady erroress / r = 1 / (1 + KKp)
  1. Simulate Kp = 1/K, 2/K and 4/K, with Ki = Kd = 0. Use the same achievable reference in all cases.
  2. Compare final error and response speed. The predicted offsets are 50%, 33.3% and 20%. Check whether the required duty exceeds the available limit.
  3. Explain: increasing P reduces offset but does not eliminate it. For this ideal first-order plant, P-only control has no overshoot. Real sampling, lag and nonlinearities can change that conclusion.

Do not confuse settling with tracking. A P response may settle quickly at the wrong speed. Report the final offset and whether it ever enters the band around the commanded target. If not, record “not settled to target”. P-only comparison is required in simulation, not as a compulsory hardware stall experiment.

3. Add integral action

For C(s) = Kp + Ki/s:

TPI(s) = K(Kps + Ki) / [τs² + (1 + KKp)s + KKi]

A persistent error makes the integral contribution accumulate. When the error reaches zero, the stored contribution can remain nonzero and supply the duty needed to keep the motor turning. For a stable, unsaturated nominal loop with Ki > 0, TPI(0) = 1. Real tracking is limited by friction, actuator authority and measurement resolution.

  1. Retain a reviewed P gain initially and add a small positive I gain. Increase I in simulation, leaving P fixed for the first comparison.
  2. Record at least three PI settings. Compare offset, overshoot, settling and duty. Larger I is not automatically better.
  3. Refine P and I as needed. Check the complete response including the zero at −Ki/Kp, not only the denominator. Use output limiting and anti-windup in the implementation check.
  4. Choose one candidate for the bench and explain why. Keep Kd = 0 unless derivative action is justified; the reported successful speed tests did not require D.

These are not three compulsory hardware exercises. Everyone completes the P/PI comparison, chooses one applicable design route and validates one controller. Structured manual refinement can follow either model-based or computational design.

Optional analytical PI starting point

For a desired nominal response Td(s) = 1/(Tcs + 1), choose Tc from the required times, not arbitrarily:

Tc ≤ min[0.50/ln(9), 1.00/ln(50)] = 0.228 s
Kp = τ/(KTc),   Ki = 1/(KTc),   Kd = 0

Tc = 0.20 s predicts a 0.439 s rise and 0.782 s 2% settling time. This nominal design cancels a stable model pole; it is a starting point, not a guarantee for the motor. The gain helper only calculates suggestions.

MATLAB / Simulink check

Use Step → Sum (+/−) → PI → Saturation → motor model → Scope, with negative speed feedback. Use motor RPM and fractional duty throughout. MATLAB: G=tf(K,[tau 1]); C=pid(Kp,Ki,0); T=feedback(C*G,1); An optional automatic starting design is C=pidtune(G,'PI');. Check target tracking separately from response-shape metrics.

Pico control interval: 10 ms; speed window: 50 ms. Do not add measurement lag twice if it is already represented in the fitted P1 model. Add D only after reviewing filtered derivative on measurement, with Tf = 0.020 s.

5. Website and motor workflow

Use practical2-control.html in desktop Chrome or Edge. Reuse the established wiring; the motor is now on the driver's Motor 1. Use the provided P2 UF2 and the P1 loading procedure only if required. Close other applications using the serial port.

  1. Connect Pico. Under Hardware setup, enter the tutor-approved actual supply, duty limit, 44 motor-shaft counts/revolution for the established decoder, applicable gearbox ratio and 10 s trial duration. Select Apply configuration. Do not use approximately 937 output-shaft counts in the motor-count field.
  2. Enter K̄ and τ̄, then select Convert P1 model → Use converted model. Compare with your own conversion. Model conversion does not apply controller gains.
  3. Enter your reviewed P/PI gains and Target motor speed (RPM). The demonstrated test used 1000 motor RPM, not 1000 output RPM. Use the target approved for your kit. Gains produce fractional duty, not percent.
  4. Select Arm & run speed trial. Observe the reference, measured speed and applied duty. STOP removes drive; allow the shaft to coast. A fault is not a completed successful run: stop, retain the data and ask the tutor before retrying.
  5. After the trial, select Analyse response → Save CSV. Save before starting another run. Stop before editing gains; change one setting at a time and explain each refinement.
  6. Freeze your final gains and record three fresh repeats at the same target. Save all attempts. Re-import one saved CSV using Load CSV and confirm the same metrics.

6. Speed targets and fair assessment

MeasureTarget
Overshoot≤ 5% of the commanded speed change beyond the final target.
Rise time≤ 0.50 s, from 10% to 90% of the commanded change. Also report t10 from the command to reveal startup delay.
Settling time≤ 1.00 s into the target-centred band, with at least 2 s final in-band dwell.
Final tracking errorLast-2-s mean absolute error ≤ max(2% of target magnitude, two speed quanta). Also report signed bias.

One speed quantum q = 60/(0.050Cm) motor RPM. Settling band b = max(0.02|rf − r0|, 2q). With Cm = 44, the floor is 54.545 RPM: at a 1000 RPM target this is ±5.45%, not strict ±2% settling. Use armed assessment data only; exclude post-stop coasting. Keep original timestamps and report any excluded pre-command transition frames. Faults, missing data or insufficient dwell cannot count as passes.

7. Submit the new P2 work

Include the carried-forward model and units; P simulations; at least three PI simulation settings; selected method and gains; initial/final hardware CSVs and reference/speed/duty plots; and three fresh final repeats. Tabulate overshoot, t10, rise, settling, final MAE/bias, actual band and duty saturation for each run.

Discuss: Why does P leave offset? How does I retain the required drive at zero error? Why can excessive I worsen the transient? Why do simulation and hardware differ? Did every final repeat pass? Do not resubmit P1 identification plots or derive the physical motor parameters again.

Optional simulation extension only: form Gθ(s) = (6/N)G(s)/s for output angle in degrees, and explore P or PD in MATLAB/Simulink. Explain the additional integrator and damping requirement. Position hardware trials are excluded: the tested position candidates faulted and are not validated bench examples.
