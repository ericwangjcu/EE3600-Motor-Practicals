Practical 2 — Motor speed feedback and PID tuning

Suggested duration: 2 hours. Work in pairs and retain individual observations. This version uses simulation; physical PID and position control are not enabled.

Learning outcomes

  • Explain the difference between an open-loop command and feedback control.
  • Use a motor model identified in Practical 1 and keep shaft-speed units consistent.
  • Tune P, PI and PID controllers and quantify overshoot, settling time and error.
  • Explain saturation, integral windup, derivative filtering and limits of simulation.
  • Extend the speed model to position and explain the additional hardware requirements.
Do not wire a motor driver or attempt physical closed-loop control for this version. Optional encoder monitoring uses the existing Practical 1 connections with motor power off. A browser Stop button is not a physical emergency stop.

Preparation and model (10 minutes)

  1. Open Practical 2. No Pico or software installation is needed for simulation.
  2. Record your Practical 1 gearbox ratio, output-speed gain and time constant. The simulator uses gearbox-output rpm and duty in percent, not motor-shaft rpm or duty fractions.
  3. If K is in rad/s/V, convert using Kduty = K × 60/(2π) × Vsupply/100. If K is already rpm/V, omit 60/(2π). Enter the measured τ unchanged. Explain why this PWM approximation may fail on real hardware.
  4. If measurements are unavailable, use the illustrative defaults: Kduty = 2.8 rpm/%, τ = 0.35 s, reference 150 rpm and output limit 100%. Label all results as simulated.

The model adds a fixed 0.08 s actuator lag. Its speed dynamics are τ·dy/dt + y = max(0, Kduty·ulag − load). The controller samples every 0.02 s. Input is applied after a 1 s baseline. The load is an equivalent speed loss in rpm, not a torque in N·m.

Check: For the default unloaded model, what duty should produce 150 rpm? What is the largest equilibrium speed with a 50% limit?

A. Open-loop response (15 minutes)

  1. Select open loop, duty 53.57%, reference 150 rpm, load 0 and duration 30 s. Apply settings, then start a new run.
  2. Observe the initial step and export the CSV. The green reference is a comparison target; it does not alter the open-loop duty.
  3. Repeat. Once settled, change load to 40 rpm and click Apply settings. Record the time of this change and the final speed.
  4. Keep the duty unchanged. Does the motor recover its reference speed? Explain using the absence of feedback.

Check: Why can an open-loop system appear accurate at one operating condition yet fail after a load change? Do not describe a load disturbance as a reference step.

B. Proportional control (15 minutes)

  1. Reset load to 0. Select closed loop, Ki = Kd = 0. Run Kp = 0.3, then 0.6, then 1.2 as separate runs. Download each CSV before starting the next.
  2. Record overshoot, observed settling time and final-window error. If the response never reaches the reference band, write “not settled”, not zero seconds.
  3. Compare response speed and persistent error with open loop. Watch for duty saturation.

For the unloaded steady-state model, yss = (KdutyKp)/(1 + KdutyKp) · r when unsaturated. Use this to check one result. The transient also includes actuator lag.

Check: Why does raising Kp reduce error without necessarily eliminating it? What is the cost of very large Kp?

C. PI and PID tuning (25 minutes)

  1. Use Kp = 0.3, Ki = 0.8, Kd = 0. Compare with P-only control. Allow the full run to finish before interpreting the final error.
  2. Increase Ki to 3 and repeat. For the default model this provides a useful overshoot example. Measured plant parameters may behave differently.
  3. Try small derivative gains, for example Kd = 0.01, 0.03 and 0.06, keeping a record of every setting. Retune Kp or Ki if necessary. Do not assume that adding derivative action must reduce overshoot.
  4. Choose gains that give a reasonable compromise between error, overshoot, settling and output effort. Explain the compromise using your results rather than labelling one set “best”.

The derivative acts on measured speed, avoiding a kick when the reference jumps. A low-pass filter reduces sensitivity to rapid measurement changes. Anti-windup stops integration that would push further into the duty limit. There is no simulated sensor noise, so you cannot assess real noise sensitivity from these runs.

Check: Why can integral action cause overshoot? Why is the numerical value of Ki dependent on whether duty uses percent or a fraction? Why might PI be sufficient for speed control?

D. Tracking, load rejection and saturation (20 minutes)

  1. Use your chosen gains, zero load and a 30 s run. After settling near 150 rpm, change reference to 100 rpm and Apply. Later change it to 180 rpm. Export the full recording; each change has a new segment ID.
  2. Repeat a 150 rpm run and apply a 40 rpm load after settling. Compare the recovery with your open-loop disturbance run.
  3. Set the output limit to 40% with reference 150 rpm and zero load. The default model cannot reach the reference. Explain why no amount of PID tuning can fix the missing actuator authority.
  4. During that run reduce the reference to 80 rpm. Observe recovery. Anti-windup is enabled; this is not a controlled comparison of anti-windup on versus off.

Gain/mode changes reset controller memory and may cause a transient. A stopped simulation resets to rest on the next run. Tabs hidden during recording automatically stop the run and retain its data.

E. Measure and compare (15 minutes)

Use the CSV and the latest unchanged segment. Do not combine several reference steps into one overshoot/settling measurement. The graph shows only the latest 20 seconds; the CSV retains the entire run.

  • Overshoot: 100 × max(0, excursion beyond the final reference in the step direction) / |reference − initial speed|. This definition also handles downward steps.
  • 2% settling time: time from the change until the response enters and stays within ±0.02 × |reference − initial speed|. The interface requires 1 s in-band and reports an observed value, which can be revoked by a later excursion. Finite observations do not prove future settling.
  • Steady-state error: reference minus final settled speed. The interface estimates this from the final 2 s after at least 3 s of a segment. If still oscillating or drifting, report it as a final-window estimate instead.
  • Load rejection: measure maximum deviation and recovery to the reference band after the load change. The automated step metrics are not a substitute for this measurement.

F. Position-control extension (20 minutes)

This is a modelling/design exercise; the browser controls speed only. Integrating output speed gives position: θ̇ = 6y in degrees/s for y in rpm. Thus Gposition(s) = 6Gspeed(s)/s in degrees/%.

  1. Draw a position-feedback loop with reference angle, controller, motor, gearbox and encoder. Explain the extra integrator relative to speed control.
  2. In MATLAB/Simulink, add an integrator and gain 6 after the speed model. Start with proportional position feedback and a small reference-angle step. Include output limits. Use a signed drive only as a clearly stated simulation assumption.
  3. Explain why a one-direction 0–100% drive cannot actively correct position overshoot. What would a verified bidirectional H-bridge and braking behaviour change?
  4. Discuss how signed encoder counts, an initial zero/reference, travel limits, backlash and cable twist affect a real position-control practical. Do not use speed gains directly for an angle-error controller: the units differ.

Before leaving: explain one limitation that could make a successful simulated controller unsafe or ineffective on the real motor.
