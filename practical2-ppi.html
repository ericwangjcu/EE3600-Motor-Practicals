Speed control with P and PI

Simulation only — no motor connection or commands. First explain the offset with P; then hold P fixed and add I. All results on this page are simulated.

Units match the Pico speed page: motor RPM and fractional duty. No gains are transferred automatically. Position is an optional MATLAB/Simulink extension only.

1. Reuse your P1 model

K = K̄ × N × 60/(2π) × Vs; τ is unchanged. No identification is repeated.

2. Compare P, then add I

P: T(s) = KKp / (τs + 1 + KKp)
PI: T(s) = K(Kp s + Ki) / [τs² + (1 + KKp)s + KKi]

The ideal unsaturated first-order P response has no overshoot, but its final error is r/(1 + KKp). PI adds a state and a zero; examine the complete response.

Convert the P1 model, then compare P-only responses. No instructor gains are preloaded.

Optional analytical PI starting point

Tc is a chosen closed-loop response time constant. For the nominal plant, rise = ln(9)Tc and 2% settling = ln(50)Tc. The practical targets require Tc ≤ 0.228 s; 0.20 s is a starting design with some ideal-model margin.

Kp = τ/(KTc), Ki = 1/(KTc). This deliberately cancels a stable nominal model pole. Simulate and inspect duty; the real motor can differ.

Model limitations

The continuous case integrates the nominal model numerically. The limited case updates the controller at 10 ms and uses exact first-order plant propagation between updates, with conditional integration. Neither includes friction, starting threshold, measurement lag, quantisation, reversal coasting, current or temperature. The encoder-aware option changes only the assessment band, not the simulated sensor. These are teaching simulations, not a replica of the firmware or proof of hardware performance. Do not add an assumed 67% minimum duty.
